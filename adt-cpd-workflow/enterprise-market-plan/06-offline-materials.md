# 离线材料与依赖交付说明

## 本次已经附带什么

本实施包包含详设、JSON示例、类型合同和三份可运行测试工具源码。工具仅使用 Node 内置模块，不新增第三方 npm 依赖，因此无需向公司镜像上传或安装新包。

create-fixtures.mjs 在离线机器上直接生成五个真实 npm tgz，包含两个 helper 版本和三个测试插件版本。它们是本次编写的合成测试制品，不从公网 npm 下载。serve-fixtures.mjs 能在本机分发这些文件，供 C01 验证真实管理器。输出 verification.json 的 fixture-only/not-run 不代表生产认证。

本次工具测试使用 Node 24.14.1；目标客户端的真实 Node/pnpm 和发行版制品必须由 C00 读取。不要把测试机器的版本自动当成公司全部终端版本。

## 公司执行前应已有的材料

| 材料 | 从哪里取得 | 由哪一步检查 |
|---|---|---|
| StarMind 指定分支源码与本实施包 | 本用户GitHub仓库相应提交 | C00 |
| pinned upstream源码/子模块 | 仓库upstream.json/.gitmodules记录的精确提交；外网导出后转入公司 | C00 |
| Node | 当前StarMind发行版已携带的兼容运行时，或公司已安装的符合根engines版本 | C00 |
| Yarn 4.18.0 | 仓库锁定的Yarn发行文件/已有Corepack缓存；禁止首次在内网动态下载 | C00/C09 |
| pnpm 11.28.5 | 当前发行版随包pnpm与相应Node入口 | C00/C01 |
| 官方dsh runtime、现有patch与vendor | 仓库vendor及发行版原始制品/manifest；不能只下载同名公网包替代 | C00/C01 |
| 整仓既有开发依赖缓存 | 公司现有开发材料；按当前yarn.lock固定版本补齐 | C00/C09 |
| 内网域名、TLS/CA与市场服务器目录 | 公司部署配置 | C00/C06 |

本包没有包含整仓所有开发依赖缓存、Node二进制或全部第三方插件。不能据此宣称全新公司电脑已经能够离线构建整个StarMind。

## 发现材料缺失怎么办

本地Agent将缺失项写入 enterprise-market/work/missing-artifacts.json，字段至少包括：用途、包/工具名、确切版本、目标系统架构、锁文件或清单来源、缺失原因、下载地址是否已验证、应放位置和校验方式。

已在公司内网的Agent不尝试访问公网，不把npm包版本改成“镜像里有的版本”，不自行添加外网fallback。把缺失清单带回外网准备环境，由准备工具取得原始字节并验证摘要，再随下一批release或构建材料转入公司。

公网npm包的实际下载地址应从精确版本manifest的dist.tarball读取，并校验dist.integrity；不能靠拼接猜测所有scope包、私有包或原生资源的下载URL。Node/Yarn/浏览器/原生资源分别使用原作者的固定版本分发信息，未经验证的地址要明确标为unverified。

## 两种离线包要分开

1. **开发构建材料**：用于公司Agent编译StarMind，覆盖根Yarn、构建器、Electron打包工具、native工具和已有workspace依赖。由C09按当前锁文件整理，不能拿运行时插件包代替。
2. **市场发布材料**：用于员工安装插件，覆盖真实宿主基线、插件依赖和运行资源。按03-server-offline.md生成release并经过目标冷验。

根build/dev/dist现有入口含刷新市场或Agents Anywhere的联网准备步骤。新增离线入口应显式检查固定版本/摘要并使用已经准备的制品，不静默改掉普通发布规则，也不执行latest刷新。

## 测试制品的发布时间策略

工具记录的是合成测试日期。若目标发行版的发布时间策略拒绝当日制品，要记录真实原因；测试Profile可以在已确认的官方机制下为这些精确合成版本设置局部测试例外，并单独记录。不能伪造上游发布时间、全局关闭策略或把测试例外带入生产配置。
